fix(install/market): 读子包不再写死 main —— 用 meta.default_branch 打头（改错，B-⑥）

动机：真机 dsh-web 全家桶的默认分支是 **dev**（不是 main）。旧代码在"懒惰展开"里写死
`fetchSubpackageNames(repo, 'main')`（读不到再手工换一次 'master'），而 meta 探测在黑洞期
失败时 branch 恒为 main → 子包列表永远读不到 → 又回到"未发现子包"的假失败。

改法（改错 + 加法，成功路径不变）：
· market.js 新增纯函数 subpackageBranchOrder(branch)：以**调用方给的分支**打头，
  再回退 main / master（去重保序；拿不到分支时行为与旧代码一致 = main → master）。
· fetchSubpackageNames 接受「单个分支名」或「分支数组」，两种形态都会带上兜底分支；
  解析逻辑（trees → packages/*/package.json → name）抽出为 fetchSubpackageNamesOnBranch，
  一个字没改；并支持 deps 注入（githubJson / rawText）以便离线断言。
· install-job：把 meta.default_branch 记进 job.defaultBranch，并交给读子包那一步
  （不再出现 `fetchSubpackageNames(job.repo, 'main'` 这种写死）。

验收：tests/test-subpackage-branch.mjs（CI 硬门槛，全部离线注入）
· 顺序：dev → main → master；分支就是 main/master 时去重；拿不到分支时退化成 main → master
· 三分支各覆盖一次：dev-only / main-only / master-only 都能读到子包，问过的分支序列如实打印
· 三条都没有 → 空数组（不假装有）；返回结构仍是 { dir, path, name }（回归保护）
· 静态断言：install-job 里不再有写死 main 的读子包调用
