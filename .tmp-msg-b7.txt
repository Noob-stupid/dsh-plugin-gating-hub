fix(git): 探活判据换成 GET info/refs + 探活失败降级到最后一轮（改错，B-⑦）

三个缺口（都是"让用户白等或白跑"的类型）：
① 探活失败的源被判**永久跳过** —— 一次瞬时抖动（DNS 刚起来、代理切换）就让唯一可用源再没机会；
② 探活用 `HEAD /`，只验"域名活着"：200 的错误页 / 登录页 / 根本不是 git 服务的镜像照样算活，
   于是白等一整个克隆超时；
③ 报错不区分"网络不可达"与"本地代理/证书拦截" —— 本机装了 Steam++ 这类加速器时用户看到的是
   `unable to get local issuer certificate`，重试永远没用，他需要的是"关掉加速器"。

改法（改错 + 加法，成功路径不变）：
· 新增 probeSourceAliveDetail → `GET <url>/info/refs?service=git-upload-pack`，2xx 时校验响应首行
  是 pkt-line（`^[0-9a-f]{4}# service=git-upload-pack`），滤掉"不是 git 服务"的镜像；
  403/405 仍按活着处理（不误杀镜像）、响应体读不到时保守按活着处理、`file://` 本地裸仓库直接算活着
  （旧代码一律判死 → 完全离线/内网共享盘场景永远用不上）；probeSourceAlive 仍是布尔（老签名不变）。
· classifyProbeFailure：证书/代理类 → "本地代理/证书拦截（…）—— 检测到本机加速器/代理，建议关闭后重试"；
  其余 → "网络不可达（…）"。归因随 errors[] 一起进用户可见的错误文案。
· gitCloneRepo：探活失败的源**降级到最后一轮**再试一次（不再 skip 定生死）；汇总文案相应改成
  "探活失败，已降级到本轮末尾重试" / "探活失败的源，已在本轮末尾重试"。

验收：
· tests/test-probe-alive.mjs（CI 硬门槛，fetch/spawn 全注入）：探活地址形状；pkt-line 通过、
  HTML 拒绝、403/405 兼容、404 拒绝、file:// 算活；证书类归因含"加速器"、DNS 类不含；
  两个源探活都失败时**真的各启动一次 git**（旧代码 0 次），首条错误即含加速器提示。
· tests/test-clone-kill-retry.mjs 相应更新（探活失败 → 本轮末尾重试，2 源 2 次）。
· 实网探针（test-git-source-strategy ⑥）：ghproxy 的 info/refs 探活 = 存活，直连 github = 不可达。
