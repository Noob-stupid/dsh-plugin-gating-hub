## 一、已交付里程碑

### 2026-09 · 自定义源全链路（v0.3.31）

**四类"源"全部可自定义，内网 / 公网 / 混合均可**

| 源 | 作用 | 能力 |
|---|---|---|
| 软件源（registry） | 下载 npm 包 | 主→备依次尝试，支持私有 / 内网 registry |
| 搜索源 | 搜索插件 / 技能 | GitHub / Gitee / 自定义 `{q}` 模板（内网搜索服务） |
| 索引源 | 市场首页清单 JSON | 主备回退、落盘缓存离线兜底、来源标识、**合并模式** |
| Git 源 | 克隆仓库代码 | `{owner}/{repo}` 模板：Gitee / GitLab / 自建 Gitea / 镜像代理 / `file://` 本地裸仓库 |

**索引合并模式**：公共索引 + 公司内网私有索引结果合并去重，同屏可见（实测 500 公共 + 2 内网私有 = 502 条）。

**内网闭环实测证据**

- 内网搜索源：本地 HTTP 服务返回 2 条内网条目 ✓
- 内网 registry：Verdaccio `127.0.0.1:4873`，元数据 24KB + tarball 拉取成功 ✓
- Git 源：Gitee 1.6s 克隆成功；`file://` 本地裸仓库完全离线克隆成功 ✓

**其他交付**

- AI 赋能：规划前用 Git 源预克隆仓库，子代理读本地材料（内网 / 离线可调研）
- 无 `package.json` 的仓库：含 SKILL.md → 自动转技能安装；否则 → 失败提示 + 一键「仓库落地」
- 软件源弹窗：加宽 + 限高 + 内置滚动条 + 五分区分折叠（软件源默认展开）
- 工程：测试进 CI（`.github/workflows/test.yml`）、测试可移植化、索引来源可观测
- 修复：`repo-clone` 凭据弹窗（`GCM_INTERACTIVE=never`）、`market-index` 405 静默失败（静态索引长期未生效）

### 2026-09 · 打开插件页提速 + 软件源扫描（v0.3.32）

- **性能**：索引补标改增量（首屏 50 条，随「加载更多」推进）+ 服务端 `/enrich` 兜底（并发 12 / 24h 缓存 / 延后 1.5s）+ 修复 `/enrich` 缓存永不命中（非官方落 `official=false`、抛错条目短 TTL）——首次 23.0s → 6.5s，缓存命中 14.1s → 4.5s；
- **软件源扫描**：软件源弹窗内一键并发探测每个源的**可达性 / 延迟 / 该源上的最新版本**，结果行内显示（`✓ 348ms · v0.3.32` / `✗ 不可达`），并汇总「N/M 可达 · 最新版本来自哪个源」；
- 新增 `test-registry-scan.mjs` 进 CI。

### 2026-09 · 框架升级/回滚健壮性四修 + 预设配置迁移门禁（v0.3.33）

> 背景：`0.1.2-rc.1 → 0.1.5-rc.1` 升级后服务反复拉不起来，复盘见 [issue #18](https://github.com/Noob-stupid/dsh-plugin-hub/issues/18)。

- **预设配置迁移门禁**：升级前扫描全部 agent 预设 + profile host 组合，把新版不再接受的字段就地改名（留 `.bak`）——0.1.5 的 `persona.text → prefix` 就是首条规则；**适配门此前只扫已装插件包，扫不到预设**，这是本次事故的真正短板；
- **启动器可见版本校验**：npx 缓存顶层 `@deepseek-ai/dsh` 若仍是 npm 时代的实体目录，pnpm 换不掉它 → 改名备份后重装一次重建链接（否则桌面端拉起的永远是旧框架）；版本校验对象从 `.pnpm` 内部路径改为顶层可见路径；
- **回滚脚本健壮化**：修正「已带引号路径又套单引号」与空串字面量导致的**全树恢复被静默跳过**；回滚体包 try/catch 并记录出错位置；
- **拉起失败有日志**：三处拉起统一 `cmd /c … >> fw-relaunch.log 2>&1`；
- 新增 `test-preset-migration.mjs`（11 断言）与 `test-upgrade-script-syntax.mjs`（生成两段 PowerShell 交解析器做语法校验）进 CI。

## 三、中期（P2 · 1–6 个月，形态演进）

| 方向 | 一句话 | 为什么值得 |
|---|---|---|
| **SDK 抽包**（首选） | 升级三件套 / AI 部署规划器 / 插件生命周期 → 3 个独立 npm 包 | 别人基于 DSH 开发软件时能引用内核而非抄代码——从"一个插件"变成"生态地基" |
| **CLI 无头模式** | `dsh-hub install / upgrade / rollback / doctor` | CI、服务器、容器镜像构建（GUI 进不去）；也是 SDK 的自然副产物 |
| **索引即 API** | 市场索引升级为对外插件发现接口 | 现有 6 小时刷新的扫描 CI 已是事实上的 registry；收录即分发 |
| **企业治理** | 私有源 + 白名单 + 版本锁定 + 签名校验 + 审计日志 | DSH 正式版后团队必问"谁能装什么插件" |
| **跨框架** | 同一套内核管 MCP servers / Claude skills / Cursor rules | 跳出单生态；风险是摊薄 |

**抽包前置与节奏**：先做工程债 #1 的按域拆分（模块边界即包边界），再抽包；hub 作为第一个消费者改为 `dependencies` 引用。已在 [Discussion #19](https://github.com/Noob-stupid/dsh-plugin-hub/discussions/19) 公开征集升级/回滚的真实踩坑反馈，作为独立包的需求池。

## 五、已知边界（诚实记录）

| 边界 | 说明 | 计划 |
|---|---|---|
| 索引"内容"仍来自本仓库 CI 扫描的 GitHub topic | 换索引源只换"下载地址"，不换"内容"；内网私有插件需自己托管一份 JSON（或用合并模式） | P1 可考虑"索引条目手动添加" |
| 技能搜索仅 GitHub 源 | 技能 tab 切到其他源会提示不支持 | P1 #1 |
| AI 赋能依赖 DSH 子代理服务 | 无 subagents 时不可用（已有明确报错） | 保持 |
| **适配门只覆盖「已装插件包 + 已登记字段改名」** | 框架改动「配置 schema」（如 0.1.5 的 `persona.text → prefix`）时，agent 预设不在门的扫描范围内——v0.3.33 已加预设配置迁移门禁兜住这一类 | 后续框架 schema 变更仍需逐条补迁移规则；欢迎在 Discussion #19 反馈漏网字段 |
