fix(install): 通道 0 异常不再短路 + release 预算跳过必须可见（改错，A-④/A-⑤）

A-④（并行竞速不设防）：旧代码里 `ch.raceInstallChannels(...)` 与其后紧跟的
`backfillMissingDeps(...)` 都在 try/catch 之外 —— 竞速实现抛一次异常（abort 竞态、
curl 摘要计算、`_tmp_` 清理）就会把 tryCandidateChannels 抛出 → runInstallJob 外层 catch
把作业判 failed → **后面的 pnpm / curl / release / git 串行通道一个都不再试**（本来可能装得上）。
现在：整段包 try/catch，异常记进 lastError + job.channelNotes，继续往下走；另有细分 ——
"curl 赢了但依赖补齐失败"只影响提示，**绝不把已经装好的包判成失败**。

A-⑤（release 预算原因不可见）：旧代码只在 `lastError === null` 时才写一句预算用尽，
于是最常见的情形（curl/pnpm 也失败）面板上完全看不出"release 通道根本没试过"。
现在原因**总是**写进 job.channelNotes；lastError 仍保留旧语义（只在没有更具体错误时才用它），
避免把 curl·pnpm 的真实原因顶掉。

验收：tests/test-channel-robustness.mjs（CI 硬门槛，通道全部注入桩、离线）
· 竞速抛异常 → pnpm/curl/release 照旧被调用，函数正常返回且备注含"并行竞速通道异常…已继续尝试后续串行通道"
· 竞速 curl 胜出 + backfill 抛异常 → installedName 保留（不误判失败），curlNote 说清"包已装好、依赖没补齐"
· release 预算 0 → channelNotes 含"release 通道因预算跳过"，且 lastError 不是那句预算文案
